Quick Start

From intake
to rendered map.

A Claude plugin that runs a structured three-skill pipeline: intake conversation, validated JSON data model, polished HTML artifact. Intake to render in one session.

Works from whatever you bring — persona docs, empathy maps, interview transcripts, support tickets, or nothing at all. Always honest about what is research-backed vs. inferred.

Step 01

Install the plugin.

The plugin runs inside Claude Code or Cowork. Installation takes about 30 seconds.

1
Download journey-mapping.plugin from the latest release.
2
Open Claude Code or Cowork → Settings → Plugins → Install from file.
3
Select journey-mapping.plugin and install.
4
Open a new session and say I want to make a journey map — the plugin activates automatically.
Step 02

Three skills, always in order.

The plugin runs as a pipeline. Each skill hands off to the next. You can stop after any skill to review before proceeding.

Skill 01
journey-map-intake
2–5 min
Intake conversation
Scans any artifacts you provide, confirms persona, establishes scenario and scope, selects map type and industry, tags what is known vs. inferred. Produces a structured intake summary. You confirm before anything is generated. Never skipped — even for a "quick" map.
↓ passes intake summary to
Skill 02
journey-map-data-model
render-agnostic
Validated JSON data model
Generates the full journey map as a structured JSON object — persona, scenario, stages, actions, thoughts, touchpoints, pain points, opportunities, emotion scores. Every pain point and opportunity is source-tagged: research, stated, or assumed. You can review and edit the JSON before rendering.
↓ passes JSON to
Skill 03
journey-map-html-render
self-contained HTML
Polished HTML artifact
Takes the JSON and renders a fully self-contained HTML file — no external dependencies, works offline. Stage matrix with SVG emotional curve, source tags on every pain point, confidence badge, and an insights panel with top pain points, opportunities, and recommended focus.

Map types

Four types, one pipeline.

All four types run through the same intake → data model → render pipeline. Select during intake, or let the plugin infer from context.

Current state
What actually happens today. Research-grounded when data exists. Use when you want to document reality, not aspiration.
Future state
The aspirational experience you're designing toward. Useful for alignment before building.
Day-in-the-life
Full daily context beyond a single product — shows where the product fits (or doesn't) in the user's broader day.
Service blueprint
Adds organizational backstage: frontstage actions, backstage employee actions, support processes — separated by a line of visibility.
Industries

Domain-aware stage libraries.

The plugin detects your industry from context and selects the right stage set automatically. No configuration needed.

Industry Stages What it detects
SaaS
 Awareness → Consideration → Sign-up → Onboarding → Activation → Retention → Expansion → Advocacy Onboarding, activation, churn, freemium, trials
AEC
 Inception → Planning & Design → Preconstruction → Construction → Commissioning → Post-Construction → Operations RFIs, submittals, permitting, change orders, delivery method
Film/TV
 Development → Pre-Production → Production → Post-Production → Distribution → Marketing → Exhibition Production accounting, unions, guilds, review cycles
General
 Awareness → Consideration → Decision → Usage → Loyalty Default when no specific domain is detected
Phase-specific
 4–6 stages derived from the scenario When mapping a slice, not end-to-end

Zone A
Header
Persona card (name, role, goal, representative quote), scenario description, scope (start → end), map type label, and confidence badge. The confidence badge is always present — a low-confidence map looks visually distinct from a high-confidence one.
Zone B
Stage matrix
Stage columns × layer rows: Actions, Touchpoints + Channels, Thoughts (in quotes), SVG Emotional Curve (smooth bezier, two-tone green/red above and below midline), Pain Points (red cards with severity dots and source tags), Opportunities (green cards with source tags). Horizontal scroll for 7+ stages.
Zone C
Insights panel
Three columns: top 3 pain points from the summary, top 2 opportunities, and the recommended focus statement — the actionable synthesis that connects the pain to the opportunity. Always rendered. This is what makes the map actionable, not decorative.
Confidence

Honest about what it knows.

Every map ships with a confidence level based on the quality of what you brought to intake. This is non-negotiable — the plugin will not dress up inference as insight.

● High
Mostly research-based. You provided transcripts, analytics, or studies. Pain points and opportunities are tagged research or stated.
● Medium
A mix of what you know and what the plugin inferred. Some research or stated sources, some assumed.
● Low
Mostly AI-generated. Thin or no research. Plugin warns before generating. Valid as a hypothesis — not valid as a decision input without validation.
